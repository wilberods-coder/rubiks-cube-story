# Кубик Рубика. Больше, чем игрушка.

Статичный образовательный лендинг на русском: HTML5, CSS3, Vanilla JavaScript, Three.js, GSAP ScrollTrigger и Lenis. Без сборщика, сервера приложений и API. Все ресурсы локальные, пути относительные. Подходит для GitHub Pages в поддиректории репозитория.

## План создания и структура

1. Семантическая разметка пяти секций в `index.html`: hero, история, механика, культурный код, footer.
2. Mobile-first стили в `style.css`: системный шрифт, чёрный/белый фон, стеклянная навигация, адаптивные сетки.
3. Модель Three.js в `script.js`: 26 деталей, 54 цветные накладки, три слоя и условная центральная крестовина.
4. Скролл: Lenis обновляется через GSAP ticker; ScrollTrigger меняет положение кубика и слоёв. История и механика используют CSS sticky. Карточки появляются с `y: 50, opacity: 0`.
5. Доступность: клавиатурная навигация, кнопки поворота и паузы, `prefers-reduced-motion`, текстовая версия без WebGL/JavaScript.
6. Проверка синтаксиса, локальных ссылок и отдачи ресурсов в поддиректории; публикация через GitHub Actions.

```text
index.html
style.css
script.js
assets/
  favicon.svg
  vendor/
    three.module.min.js
    gsap.min.js
    ScrollTrigger.min.js
    lenis.min.js
    licenses/
.github/workflows/pages.yml
.nojekyll
```

## Локальный запуск

Из этой папки:

```sh
python3 -m http.server 4173 --bind 127.0.0.1
```

Откройте http://127.0.0.1:4173/. Нужен HTTP-сервер: ES-модули могут не работать при открытии `index.html` через `file://`.

## Как устроен script.js

- `setupMotion()` создаёт Lenis и GSAP context. При паузе context отменяется, Lenis уничтожается, возвращается обычный скролл.
- `setupThree()` загружает Three.js через относительный dynamic import. Ошибка импорта или WebGL оставляет текстовую версию.
- `createScene()` строит 26 деталей и добавляет накладки только на внешние грани. Геометрии и материалы общие для двух сцен.
- Один `WebGLRenderer` рисует обе сцены через viewport/scissor в пределах соответствующих блоков. Невидимые сцены пропускаются.
- GSAP меняет числовые значения в `state`; рендерер переносит их в вращение и раздвижение слоёв.
- Внутренний механизм показан условно: это объясняющая схема, а не производственный CAD.
- При публикации на `*.github.io` ссылка footer определяется по адресу страницы и ведёт в репозиторий.

## Производительность и доступность

Один WebGL-контекст, общая геометрия и материалы, без текстур, теневых карт и постобработки. DPR ограничен 1.5 на компьютере и 1.25 на узком экране. На узком экране рендер ограничен 30 fps. Скрытая вкладка не рендерится; при паузе повторный рендер нужен только после изменения состояния/прокрутки. Touch-прокрутка нативная.

На телефоне история идёт обычной вертикальной лентой, чтобы длинный текст не перекрывался sticky-блоком. Механика сохраняет sticky-разбор. В режиме уменьшенного движения длинная sticky-механика заменяется статичной раскрытой моделью.

## GitHub Pages

1. Поместите содержимое этой папки в корень репозитория с основной веткой `main`.
2. В Settings → Pages → Build and deployment выберите **GitHub Actions**.
3. Workflow `Publish to GitHub Pages` публикует страницу при push в `main`; при необходимости запустите его вручную.
4. Адрес проекта: `https://USERNAME.github.io/REPOSITORY/`.

В workflow публикуются только публичные файлы сайта. Установка npm-пакетов и сборка не нужны. Инструкция GitHub: https://docs.github.com/en/pages/getting-started-with-github-pages/using-custom-workflows-with-github-pages
